# a11y-audit MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the a11y-audit TypeScript MCP server — axe-core WCAG accessibility analysis via Playwright headless Chromium, returning typed violation reports with rule IDs and DOM selectors.

**Architecture:** A11yAuditor launches a single Playwright browser instance at startup and reuses it across calls. For each audit, it opens a new page, navigates to the URL or file:// path, injects axe-core via @axe-core/playwright, runs the analysis, and returns typed AuditResult. Browser is closed cleanly on SIGTERM/SIGINT. All logging via console.error.

**Tech Stack:** Node.js 20+, TypeScript 5+, `@modelcontextprotocol/sdk`, `playwright`, `@axe-core/playwright`, `zod`, `vitest`

---

## Background

[axe-core](https://github.com/dequelabs/axe-core) is the industry-standard accessibility testing engine. It evaluates a rendered DOM against WCAG 2.x success criteria and returns four result buckets: `violations`, `passes`, `incomplete` (needs human review), and `inapplicable`. Automated testing with axe-core catches roughly 57% of WCAG issues — the remainder require human judgment — so this skill is a quality gate, not a guarantee of compliance.

[@axe-core/playwright](https://www.npmjs.com/package/@axe-core/playwright) is the official integration that injects axe-core into a Playwright page and runs it. The `AxeBuilder` API supports filtering by rule ID, WCAG tag, and impact level.

This MCP server renders HTML files or React component output (already built to static HTML, or a dev-server URL) in headless Chromium, runs axe-core, and returns a typed violation report. No LLM inference is involved. It exists so the Labmate orchestrator can run it as a post-generation QA gate on any frontend code.

**Three tools exposed:**
- `a11y_audit.audit_file(html_or_component_path, rules?)` — render a local file in headless Chromium, run axe-core, return JSON
- `a11y_audit.audit_url(url, rules?)` — same but for an http(s) URL
- `a11y_audit.list_rules()` — list available axe-core rule IDs with WCAG level

**Critical rules (non-negotiable):**
- stdout is sacred: NEVER `console.log()`. ALWAYS `console.error()` for logging. stdout carries JSON-RPC 2.0.
- Launch the Playwright browser ONCE at startup; reuse it across tool calls; close on SIGTERM/SIGINT. Never launch-per-call.
- Use `@axe-core/playwright`: `import { AxeBuilder } from "@axe-core/playwright"` (or `require`).
- `PLAYWRIGHT_BROWSER = process.env.PLAYWRIGHT_BROWSER ?? "chromium"` — never hardcode.
- If the browser fails to launch or a page fails to load, return a structured error object — never crash the server.
- TypeScript files: camelCase.ts. Interfaces: PascalCase.

## Phase 3 — A11yAuditor (Playwright + axe-core)

### Task 3.1 — Scaffold the A11yAuditor class with browser lifecycle

- [ ] Create `services/skills/a11y-audit/src/auditor.ts` with browser launch/reuse/close. The browser is launched lazily on first use and reused; `close()` is idempotent.

```typescript
// auditor.ts — A11yAuditor: launches one headless browser, reuses it across audits
import { chromium, firefox, webkit, Browser, BrowserType } from "playwright";
import { AxeBuilder } from "@axe-core/playwright";
import { pathToFileURL } from "node:url";
import { resolve } from "node:path";
import type { AuditResult, Violation, RuleInfo, WcagLevel, Impact } from "./types.js";

const BROWSER_NAME = process.env.PLAYWRIGHT_BROWSER ?? "chromium";

function browserType(name: string): BrowserType {
  switch (name) {
    case "firefox":
      return firefox;
    case "webkit":
      return webkit;
    case "chromium":
    default:
      return chromium;
  }
}

export class A11yAuditor {
  private browser: Browser | null = null;

  /** Launch the browser once; subsequent calls reuse the same instance. */
  private async getBrowser(): Promise<Browser> {
    if (this.browser && this.browser.isConnected()) {
      return this.browser;
    }
    console.error(`[a11y-audit] launching ${BROWSER_NAME} (headless)`);
    this.browser = await browserType(BROWSER_NAME).launch({ headless: true });
    return this.browser;
  }

  /** Close the browser cleanly. Idempotent. */
  async close(): Promise<void> {
    if (this.browser) {
      console.error("[a11y-audit] closing browser");
      await this.browser.close();
      this.browser = null;
    }
  }

  // audit() / auditFile() / auditUrl() / listRules() added in later tasks
}
```

### Task 3.2 — Map WCAG level from axe tags

- [ ] Add a private helper to `A11yAuditor` that derives `wcag_level` from axe rule tags. axe tags include `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag2aaa`, etc. Highest level present wins; default to `"A"` when no wcag tag is found.

```typescript
  private wcagLevelFromTags(tags: string[]): WcagLevel {
    const has = (frag: string) => tags.some((t) => t.includes(frag));
    if (has("aaa")) return "AAA";
    if (has("aa")) return "AA";
    return "A";
  }
```

### Task 3.3 — Core audit() that runs axe on an already-loaded page URL

- [ ] Add the shared `audit()` method. It opens a new page, navigates, runs AxeBuilder (optionally filtered by `rules`), maps results to typed `AuditResult`, and always closes the page in a `finally`. Errors are thrown for the caller to convert into a structured `AuditError`.

```typescript
  /**
   * Navigate to a URL (http(s) or file://), run axe-core, return typed result.
   * @param navTarget fully-qualified URL the browser can load
   * @param label human-readable url_or_path echoed back in the result
   * @param rules optional axe rule IDs to restrict the run to
   */
  async audit(
    navTarget: string,
    label: string,
    rules?: string[]
  ): Promise<AuditResult> {
    const browser = await this.getBrowser();
    const page = await browser.newPage();
    try {
      const response = await page.goto(navTarget, {
        waitUntil: "networkidle",
        timeout: 30_000,
      });
      // file:// returns null response; only treat http(s) non-2xx as failure
      if (response && !response.ok()) {
        throw new Error(
          `page load failed: HTTP ${response.status()} for ${label}`
        );
      }

      let builder = new AxeBuilder({ page });
      if (rules && rules.length > 0) {
        builder = builder.withRules(rules);
      }
      const results = await builder.analyze();

      const violations: Violation[] = results.violations.map((v) => ({
        id: v.id,
        impact: (v.impact ?? "minor") as Impact,
        description: v.description,
        wcag_level: this.wcagLevelFromTags(v.tags),
        nodes: v.nodes.map((n) => ({
          html: n.html,
          target: n.target.map((t) => String(t)),
          failure_summary: n.failureSummary ?? "",
        })),
      }));

      return {
        url_or_path: label,
        violations,
        passes: results.passes.length,
        incomplete: results.incomplete.length,
        inapplicable: results.inapplicable.length,
        violation_count: violations.length,
      };
    } finally {
      await page.close();
    }
  }
```

### Task 3.6 — listRules() returns the axe rule catalog

- [ ] Add `listRules()`. axe-core exposes its rule metadata via `axe.getRules()` evaluated inside a blank page. Load `about:blank`, inject axe via a no-rule AxeBuilder run is unnecessary — instead evaluate the bundled axe source. Use `@axe-core/playwright`'s injection by running `analyze()` once is wasteful; instead read rules from the `axe-core` package directly in the page context.

```typescript
  async listRules(): Promise<RuleInfo[]> {
    const browser = await this.getBrowser();
    const page = await browser.newPage();
    try {
      await page.goto("about:blank");
      // AxeBuilder injects axe into the page; trigger injection then read getRules()
      await new AxeBuilder({ page }).analyze();
      const rules = await page.evaluate(() => {
        // @ts-expect-error axe is injected into window by AxeBuilder
        return (window.axe.getRules() as Array<{
          ruleId: string;
          description: string;
          tags: string[];
        }>).map((r) => ({
          id: r.ruleId,
          description: r.description,
          tags: r.tags,
        }));
      });
      return rules.map((r) => ({
        id: r.id,
        description: r.description,
        wcag_level: this.wcagLevelFromTags(r.tags),
        tags: r.tags,
      }));
    } finally {
      await page.close();
    }
  }
```

# a11y-audit

Runs [axe-core](https://github.com/dequelabs/axe-core) against a rendered DOM in headless
Chromium (Playwright) and reports WCAG violations. This is an automated gate, not a
guarantee — axe-core detects roughly 57% of WCAG issues; the rest need human review.

### `a11y_audit.audit_file(html_or_component_path, rules?)`
Resolves the path to a `file://` URL, renders it, injects axe-core, and returns an

Each violation carries: `id` (rule), `impact` (critical | serious | moderate | minor),
`description`, `wcag_level`, and `nodes` (each with `html`, `target` CSS selectors, and
`failure_summary`).

- Triage by `impact`: fix `critical` and `serious` first.
- `incomplete` means axe could not decide — review those manually.
- A zero `violation_count` does NOT mean fully accessible; it means no automated failures.

- `PLAYWRIGHT_BROWSER` — `chromium` (default), `firefox`, or `webkit`.
